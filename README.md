# 運転日報

社用車の選択、運転前点検、出発・帰着、アルコール確認を記録する独立したWebアプリです。画面はGitHub Pages、APIはGoogle Apps Script（GAS）、保存先はGoogleスプレッドシートを使います。

GitHub Pagesと運転日報GASは公開済みで、`config.js` の `apiUrl` とキンジロー君側の `DRIVE_DIARY_APP_URL` を設定しています。日報データの操作にはキンジロー君認証が必要です。この配布では共有招待キーを設定・配布しません。再構築する場合は以下のGAS設定・管理者の認可・Webアプリのデプロイが必要です。

## ローカルで確認する

Node.js 22を推奨します。現在の実装はNode.jsの標準機能だけで動くため、依存パッケージのインストールは不要です。

```sh
npm run dev
```

ブラウザで `http://127.0.0.1:8787/?demo=1` を開きます。入口の見た目は `http://127.0.0.1:8787/preview/kinjiro-entry.html` で確認できます。

同じブラウザで `http://127.0.0.1:8787/?demo=1&demoUser=handover` を開くと、本人を `2002` / `引継ぎ運転者（デモ）` に切り替え、通常デモで出発した記録を別の担当者として完了する流れを確認できます。

デモの48台、本人情報 `1001` / `デモ運転者`、距離や履歴は架空データです。デモでも氏名は自動表示し、社員番号による検索は行いません。`?demo=1` の操作は本番GAS・スプレッドシートに送信しません。デモ状態はそのブラウザ内で保持されます。

```sh
npm test
npm run build
```

`npm test` はNode.jsのテストを実行し、`npm run build` は公開用の画面と画像を `dist/` に用意します。テストでは実際のGASや本番シートに接続しません。

## 操作と保存内容

1. 最初に選択画面で稼働部門とお気に入りの車番を選び、キンジロー君で認証された本人の氏名を確認します。アプリを開いた直後に、以前の運転中記録を自動で開くことはありません。
2. 「次へ進む」を押すと、選択車両の最新状態を取得します。運転中の記録がなければ出発画面、あればその記録の完了画面へ進みます。
3. 出発画面で対象点検をすべて確認し、運転前の酒気帯びを「無」にすると出発できます。開始スライドを操作すると、選択車両のシートへ日付・曜日・開始時刻・運転者・点検結果を記録します。
4. 帰着時も選択画面で部門と車番を選び、「次へ進む」で完了画面を開きます。行先・終了メーター等を入力して終了スライドを操作すると、開始時と同じ行を更新します。

- 日付と時刻はGAS側の日本時間を使います。
- 同じ車両の重複開始を防ぎます。通信結果が不明なときの再送は、同じ記録ID・通信IDで処理し、二重記入を防ぎます。
- 出発者と別の認証済み担当者も完了できます。日報の「運転者」欄には「出発者名 ／ 完了者名」を記録し、同じ社員番号なら出発時の氏名だけを記録します。出発者・完了者の社員番号と氏名は認証情報から保存します。
- 出発時と完了時の稼働部門は、管理シートへ別々に保存します。出発部門は上書きせず、日報の19列も増やしません。旧版の画面が完了部門を送らない場合は、出発部門を使います。
- 終了メーターから出発メーターを引いて走行距離を求めます。終了値が出発値より小さい場合は保存しません。
- 給油量は給油チェック時だけ保存し、0より大きいリットル数が必要です。オイル交換チェック時は「実施」を保存します。
- 前後の確認チェックは「OK」または空欄、検知器の未入力は空欄、数値0は `0.00` です。前後どちらかの酒気帯びが「有」なら共通欄を「有」にします。指示事項は空欄です。
- 運転前の酒気帯びが「有」の間は、出発スライドと代替ボタンを操作できません。GASでも出発を拒否します。運転後の「有」は確認結果として記録できます。
- 点検は通常9項目です。社用車一覧に任意の「変速機」または「ミッション」列があり、値が `MT` の車だけクラッチ確認を追加します。

稼働部門は、GAS側で設定した13種類から選択します。

お気に入りは最大10台で、端末のブラウザ内に認証された本人ごとに保存します。メインの車両プルダウンにはお気に入りだけを表示します。0台のときは「お気に入りを登録してください」と登録ボタンを表示し、全48台へ自動的に切り替えません。登録画面では全車両から追加・解除できます。他の端末やブラウザには引き継がれません。

選択済みの車番は次回へ引き継ぎません。アプリを開く・選択画面へ戻る・完了後に次の運転を始める場合は、車両欄を「車両を選択してください」に戻します。選択画面を表示したまま別のアプリやタブへ移動し、戻った場合も選び直します。お気に入りの登録は保持し、出発・完了の保存結果が未確認の操作は元の車両と通信IDを保持して、明示した再確認操作で処理します。

入力途中の内容、通信確認待ちの操作、端末に保持する運転中の記録も本人ごとに分けます。他の社員の確認待ち操作は再送できません。旧版の下書きは本人が一致する場合に引き継ぎ、実行者を特定できない旧版の完了確認待ちデータは元の端末に保持して自動再送しません。

## スプレッドシートの構成

実データはスプレッドシート内で管理します。列位置は固定せず、以下の見出し名で検索します。

### 社用車一覧

- A「車番」
- B「車種」：ハイエース、ハイゼット、サクシード、プロボックス、トヨエース
- C「種別」：ガソリンまたは軽油
- D「車検満了日」
- E「初回確認時のオイル交換実施距離」
- F「初回確認時の距離」
- G「現在の距離」
- H「運転日誌リンク」：各車両シートの `gid` を含むリンク

EとFは管理者が実際の値を入力します。**完了済み記録がまだない初回は、Fが空なら開始できません。空欄を0で補完しません。入力済みの0は有効です。** 初回の出発距離はF、その後は完了日時が最新の記録の終了メーターを使い、Fの有無には依存しません。Gだけを初回距離の代わりには使いません。終了時にGを更新し、E・Fは上書きしません。

**Eが空ならオイル交換基準は「未登録」です。Fを交換基準に流用しません。** Eが入力されれば初回基準に使い、その後はオイル交換を「実施」とした完了記録の終了メーターを優先します。交換間隔はガソリン7,000km、軽油4,000kmです。残り50km未満でお知らせを表示します。オイル交換のお知らせは、アプリで車両を選択・確認したときに表示します。車検満了日は車両情報として保持し、アプリ内のポップアップからは除外します。

Hのリンク先gidを優先して車両シートを解決し、リンクが使えない場合は車番とシート名を照合します。識別時は全角半角・空白を正規化しますが、元の車番やシート名を書き換えません。

### 運転者情報

運転日報スプレッドシートの「社員一覧」は不要です。社員番号と氏名は、運転日報GASがキンジロー君の `deviceVerify` で検証した本人情報を `bootstrap.employee: { id, name }` として返します。氏名の信頼元はキンジロー君側の認証応答の `empName` です。出発者と完了者はそれぞれの操作時に認証された本人を記録し、出発者と異なる認証済み社員も完了できます。画面から送られた氏名で本人情報を差し替えることはできません。本番GASをこの実装へ更新・再デプロイした後、既存の「社員一覧」シートは削除できます。社員情報は公開リポジトリへ入れません。

### 各車両シート・運転日報ひな形

セル結合なし、1項目1列、1記録1行の19列を使います。以下は見出しの並びです。

```text
日付 / 曜日 / 運転前車両点検 / 出発時間 / 終了時間 / 運転者 / 行先 / 出発メーター(km) / 終了メーター(km) / 走行距離(km) / 給油量(L) / オイル交換 / 備考・不具合 / 運転前対面確認者 / 運転前検知器結果(mg/L) / 運転後対面確認者 / 運転後検知器結果(mg/L) / 酒気帯び(有/無) / 指示事項
```

稼働部門・記録ID・通信ID等は19列へ追加せず、次の管理シートへ保存します。管理者がスプレッドシート内で確認できるよう、タブを表示します。

- `_運転日報_記録管理`：記録ID、車両、運転状態、稼働部門等
- `_運転日報_リクエスト`：再送判定と途中失敗からの回復情報

管理シートと運転中の記録行はアプリで管理します。手動変更で開始行との一致が崩れると、別の行を上書きせず `ROW_CONFLICT` で停止します。

### テスト記録の取消

Gの現在距離や日報の距離セルを消しても、管理シートの完了記録が残るため開始メーターは戻りません。テストを戻すときは管理者が記録単位で取消を行います。取消済み記録は距離・オイル交換の計算と通常の履歴から除外し、元の記録と取消理由は管理シートに保持します。同じ通信IDの再送も `TRIP_CANCELLED` で拒否します。

取消は対象車両の最新記録から順に行い、後続の運転記録がある途中の記録は取り消せません。日報の19項目を空欄に戻し、現在距離は残っている最後の完了メーター、完了記録がなければFの初回確認距離に戻します。行番号をずらす行削除は行いません。取消操作はGAS所有者が実行する非公開の管理処理で、社員用画面やWeb APIには公開しません。

完了者や完了部門が未保存の旧記録は、出発者の氏名と出発部門を使って表示します。旧記録の保存済み通信結果を再確認する場合も、元の操作を行った本人に限ります。

## GASの設定

以下の `<...>` はすべて置換用の記号です。実際の接続先・ファイルID・秘密値はこのREADMEへ追記せず、設定先へ直接登録します。

1. 対象スプレッドシートへアクセスできる管理用GoogleアカウントでApps Scriptプロジェクトを作ります。
2. `gas/Code.gs` をコードとして配置し、プロジェクト設定でマニフェストを表示して `gas/appsscript.json` の内容を設定します。
3. プロジェクト設定の「スクリプト プロパティ」に次を登録します。

- `SPREADSHEET_ID`：`<SPREADSHEET_ID>`。記録先ブックのファイルID。
- `KINJIRO_VERIFY_URL`：`<KINJIRO_GAS_EXEC_URL>`。既存キンジロー君の `deviceVerify` を処理する固定のGAS `/exec` URL。キンジロー君連携時に必要です。
- `ALLOWED_ORIGINS`：`["<PAGES_ORIGIN>"]` の形のJSON配列。Pagesの `https://ホスト名` 部分を完全一致で登録し、リポジトリ名のパスや末尾の `/` は含めません。ローカルの実API確認をする場合だけ、そのローカルoriginも明示して追加します。
- `ACCESS_KEY`：現行の配布では使いません。設定済みの場合も、キー単独では本人を特定できないため操作できず、キンジロー君の本人認証が必要です。

4. 管理者がGoogleの権限確認を行います。管理シート2枚は、デプロイ後、正常に認証された最初の車両詳細取得（`vehicleContext`）で自動作成されます。既存の管理シートが非表示の場合も、次の利用時に表示へ戻します。`setup_` の手動実行は不要です。未認証リクエストや稼働確認だけでは作成されません。
5. 本番設定を確認した段階でWebアプリとしてデプロイします。実行ユーザーは所有者、アクセス設定は追加のGoogleログインなしでAPIを呼べるものを選びます。組織の設定でこの公開方法が制限されている場合は管理者側で確認してください。公開URLに到達できるだけでは日報データを操作できず、各操作でキンジロー君認証を検証します。
6. 発行された運転日報GASの `/exec` URLを `config.js` の `window.DRIVE_CONFIG.apiUrl` に設定します。`/dev` URLは配布しません。ここには接続先だけを置き、社員情報・トークン・ACCESS_KEYは入れません。

画面は `bootstrap`、`vehicleContext`、`startTrip`、`finishTrip`、`getTrip`、`listHistory` を使います。`bootstrap` は車両・部門と認証本人の社員番号・氏名を返します。GASの `lookupEmployee` は互換用として本人情報だけを返し、画面からは呼びません。認証は各操作で検証します。通常のJSON POSTに加え、許可originへの `postMessage` によるiframe通信にも対応しています。`doGet` は非機密の稼働確認だけです。

GASコードを更新したときは、Webアプリのデプロイも新しいバージョンへ更新してください。

## キンジロー君から開く

主な入口はキンジロー君の「稼働情報（必須）」の下にある運転日報ボタンです。キンジロー君側 `index.html` の `DRIVE_DIARY_APP_URL` は作成済みのPages公開先に設定済みです。公開先を変更する場合は、この値も更新します。

日報画面上部の「キンジロー君に戻る」から、[キンジロー君の画面](https://m8i-kintai.github.io/kintai-pwa/)へ戻れます。

ボタンは既存の社員番号・端末トークンをURLのfragmentとして運転日報へ渡します。運転日報GASがサーバー側で、設定済み `KINJIRO_VERIFY_URL` へ `requestType: "deviceVerify"` と社員番号・トークンを送り、応答が `status: "ok"` で、必須の `empId` が受け渡された社員番号と一致し、氏名 `empName` を取得できた場合だけ受け付けます。運転日報用の追加ログイン画面はありません。

受け取った機密値はそのタブの `sessionStorage` へ保持し、読み込み後にアドレス欄から取り除きます。トークン失効時はキンジロー君で認証を更新して開き直します。GASはトークンと社員番号のハッシュをキーに約120秒だけ認証結果をキャッシュします。開始時は認証本人を出発者、完了時はその操作をした認証本人を完了者として保存します。同じ通信IDの再送は、出発なら出発者、完了なら完了者と同じ本人に限ります。検証URLをクライアントから指定する仕組みにはしていません。

社員番号・氏名を確実に本人へ結び付けるため、キンジロー君のボタンから開いて利用します。共有招待キーだけのリンクでは操作できません。認証情報の実値はソース、README、画面設定、Actionsログへ記載しません。

## GitHub Pagesへの公開

GitHub Freeでは公開リポジトリからのPages公開を前提にします。コードと一般公開できる画像だけを管理し、実際の日報・車両マスター・社員情報はGoogle側へ保持します。無料プランの公開範囲は[GitHub公式のPages説明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)で確認できます。

1. 公開するファイルを確認し、公開リポジトリの `main` ブランチへこのアプリのソースを登録します。`design/`、`.local-preview/`、ローカル資料、`.env*`、GASの秘密設定や認証ファイルは登録しません。`.gitignore` も確認してください。秘密値を含まない `gas/Code.gs` とマニフェストはコードとして管理できます。
2. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にします。
3. `config.js` のAPI接続先、GASのScript Properties、キンジロー君側の公開先設定を確認してから `main` へpushします。手動の場合はActionsの「Deploy GitHub Pages」を `main` ブランチで実行します。
4. `.github/workflows/pages.yml` がNode.js 22で `npm test`、`npm run build` を実行し、生成された `dist/` だけをPagesへデプロイします。リポジトリ直下をそのまま公開する設定にはしません。
5. 公開URLから入口・車両選択・認証を確認します。実データへの開始・終了の確認は、管理者が指定した車両・条件で実施します。

workflowはGitHub公式のcheckout、setup-node、configure-pages、upload-pages-artifact、deploy-pagesを使います。Pagesへの書込み権限はdeployジョブに限定しています。構成の詳細は[GitHub公式のカスタムworkflow手順](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)を参照してください。

無料枠には上限があります。Pagesにはサイトサイズ・帯域等、GASには実行時間・同時実行・サービス呼出し等の制限があり、利用状況やアカウントによって影響を受けます。[Pagesの利用上限](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)、[GASの割当と制限](https://developers.google.com/apps-script/guides/services/quotas)を確認してください。

## 主なエラー

- `UNCONFIGURED` / `CONFIGURATION_ERROR`：公開先・API・Script Propertiesの設定を確認します。
- `UNAUTHORIZED` / `KINJIRO_SESSION_EXPIRED`：キンジロー君から開き直します。
- `EMPLOYEE_MISMATCH`：出発者の指定や同じ通信IDの再送が、認証された本人と一致しません。キンジロー君から開き直します。
- `ALCOHOL_PRESENT`：運転前の酒気帯びが「有」のため出発できません。
- `KINJIRO_VERIFICATION_UNAVAILABLE`：キンジロー君認証先との通信を確認します。
- `INITIAL_ODOMETER_REQUIRED`：管理者がFの初回確認距離を登録します。
- `VEHICLE_IN_USE`：その車両の運転中記録を確認します。
- `TRIP_CANCELLED`：管理者が取り消した記録です。保存待ちの再送を終了し、車両を選び直して最新のメーターを確認します。
- `ROW_CONFLICT` / `SCHEMA_ERROR`：見出し、車両リンク、管理シート、対象行の手動変更を管理者が確認します。
- 通信失敗や保存結果不明：画面の再確認操作を使います。同じ操作を新規記録として作り直すと、結果の追跡が難しくなります。

本番での利用にはオンライン接続が必要です。
